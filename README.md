# K1 验收台

K1 验收台包含配置向导、版本日验收、分支验收、节点管理和批次详情。服务端使用 DWS 读取真实进包表，执行节点独立领单，并通过事件流回传 Claude Code 输出。静态交互示例位于 `public/`。

克隆后可把 [Agent 部署说明](DEPLOY.md) 交给 Agent，按主服务器或执行节点的角色部署。

## 服务端与执行节点

当前部署配置用于只读链路联调。批次记录 Git 版本核对和 AI 输出，条目结果显示阻塞或待补验。运行时业务验收、自动部署和进包表回写需要相应执行环境与配置。

1. 在部署账号下安装 Python 3.9 或以上、Git、DWS 和 Claude Code。先用该账号分别确认 DWS 可以读进包表、Claude Code 可以运行。节点还需要对应的 Unity 或真机环境。
2. 选择部署主机上可写的运行目录。Mac 节点初始配置可用 `python3 provision.py --directory <运行目录> --node-root <三端工程根目录> --unity-editor <Unity可执行文件绝对路径>`。运行目录包含数据库、节点令牌、操作员口令和节点持久化数据，和代码分开放置。
3. 在仓库根目录运行 `python3 server.py --config <运行目录>/server.json` 和 `python3 worker.py --config <运行目录>/node.json`。默认监听 `127.0.0.1:8082`，通过受保护的 SSH 转发或已有 HTTPS 入口访问。网页登录使用 `server.json` 中生成的操作员和口令。节点平台为 Windows 时，从网页登记节点，再用颁发的节点标识和令牌复制一份节点配置，并改成本机路径及服务地址。
4. 三端工程根目录下应有 `K1Client/k1_client`、`K1Game/game` 和 `K1Dataconfig/dataconfig`。节点在缺少技能仓库时从配置的来源克隆，保存配置后可在网页查看检查结果。

SSH 转发示例。

```bash
ssh -N -L 8082:127.0.0.1:8082 <部署账号>@<部署主机>
```

转发启动后，在浏览器打开 [http://127.0.0.1:8082](http://127.0.0.1:8082)。

macOS 上如果 DWS 通过钥匙串读取登录态，请从可以直接读取进包表的本机登录终端启动网页服务。SSH 会话中的 DWS 状态可能与该终端不同。执行节点进程和批次数据库可以继续使用原有配置。

本地运行工作簿兼容性检查使用 `python -m unittest discover -s tests -v`。用真实进包表联调时，选择至少有一条「待验收且已合进 dev」记录的页签，并从详情页核对节点、版本与实际 AI 输出。

## 启动静态网页

在目标主机检出仓库，从仓库根目录执行。以下命令使用 Python 3 自带的静态服务。

**macOS**

```bash
python3 -m http.server 8080 --bind 127.0.0.1 --directory public
```

**Windows**

```powershell
py -3 -m http.server 8080 --bind 127.0.0.1 --directory public
```

本机预览打开 [http://127.0.0.1:8080](http://127.0.0.1:8080)。需要从其他内网机器访问时，将 `--bind` 后的地址替换为部署主机的内网 IP，再用该 IP 和实际端口访问。端口已占用时，选一个可用端口并在交付时写明。前台运行时用 Ctrl+C 停止。如果要求退出远程会话后继续提供服务，使用部署主机的服务管理方式启动，并验证退出会话后 URL 仍可打开。

## 部署验证

- [ ] 从预期访问设备打开 URL，确认能加载 K1 验收台。首次体验用空白浏览器配置或无痕窗口。
- [ ] 在配置向导选择 Mac 或 Windows 节点，点「填入示例路径」「检查配置」「保存并进入验收台」。
- [ ] 选择「版本日验收」，刷新示例页签并提交一批。打开队列详情，确认看到验收清单、进度及可展开的 AI 输出。
- [ ] 选择「分支验收」，点「填入示例」并提交一批。打开详情，确认显示目标功能分支、测试用例及逐段更新的模拟输出。
- [ ] 记录实际 URL、部署路径、运行方式和停止或重启方法。

节点配置和批次记录保存在访问者浏览器中。更换浏览器或访问地址时会从空白状态开始。正式版的钉钉接入、调度服务和执行节点以实施方案为准。
